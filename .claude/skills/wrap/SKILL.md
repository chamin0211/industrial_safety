# /wrap — 세션 마무리와 기록

다음 대화의 Claude가 이어서 할 수 있도록 기록을 남긴다. 기록은 **개발자의 말**이 중심이다.

## 1. 오늘 한 일 정리 (Claude가 초안)

- 이번 대화에서 한 작업, 만든 파일, 해결한 오류를 3~5줄로 정리해 보여 준다.
- 작업 목록 기준으로 어디까지 했는지(완료 / 진행 중 / 막힘) 표시한다.

## 2. 개발자에게 묻기 (한 번에 묻고 답을 기다린다)

1. **오늘 배운 개념**을 자기 말로 한두 문장씩 설명해 주세요.
2. **아직 헷갈리는 것**이 있나요?
3. 대략 **몇 시간** 했나요?

- 개발자가 "모르겠다", "없다"라고 해도 괜찮다. 그대로 기록한다.
- 설명에 틀린 부분이 있으면 기록 전에 부드럽게 짚고, 개발자가 다시 말한 내용을 기록한다.

## 3. 기록하기

### docs/learning-log.md

- "세션 기록" 맨 위에 새 항목을 추가한다(최신이 위). 파일 안의 형식을 따른다.
- "배운 개념 (자기 말로)"에는 개발자의 답을 **다듬지 않고 그대로** 옮긴다.
- 헷갈리는 것은 "아직 헷갈리는 개념" 목록에도 추가한다.
- 오늘 이해했다고 확인된 개념이 "아직 헷갈리는 개념"에 있으면, 지우고 "이해한 개념" 표로 옮긴다.
- `/debug`에서 나온 오류 한 줄 요약이 있으면 "복습할 것"에 넣는다.

### docs/progress.md

- "지금 위치"를 갱신한다: 단계, 진행 중인 작업과 어디까지 했는지, 다음 할 일.
- 체크리스트에서 끝난 항목을 체크한다. 단, 작업 완료는 **테스트 통과 + 이해 확인**이 끝난 경우에만 체크한다(D9).
- "최근 세션"에 한 줄을 추가하고, 3개를 넘으면 가장 오래된 것을 지운다.
- 파일이 길어지지 않게 유지한다(대화 시작마다 자동으로 읽히므로).

## 4. 마무리 안내

- 무엇을 기록했는지 짧게 보여 준다.
- 다음에 시작할 때 `/lesson`이라고 하면 이어서 진행된다고 알려 준다.
- 커밋할 만한 시점이면 **커밋 명령과 메시지 예시를 알려 주고**, 실행은 개발자가 한다(AGENTS.md Git 규칙).

## 지키는 것

- 기록 파일(docs/) 외에는 수정하지 않는다.
- 개발자가 말하지 않은 내용을 "배운 것"으로 지어 쓰지 않는다.
