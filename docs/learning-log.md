### 2026-11-23 · 준비 1주차 · 제조업 사례 전체 받기와 방향 확인

- 한 일: `scripts/fetch_manufacturing_cases.py` 작성·실행 성공(제조업 1,463건을 15페이지로 받아 `data/raw/disaster_cases/manufacturing_cases.json`에 저장, 건수 일치). 제목 끝 표현 세기로 옛/새 분류명 혼재(협착=끼임, 추락=떨어짐), 종류를 알 수 없는 끝 단어(사망·사고·발생), "누출"이 끝 단어에 거의 없음을 확인. 키워드 세기·전체 분류는 제품에 필요 없어 중단하고, "작업 입력 → 시스템이 비슷한 사례를 찾음"이라는 PLAN 방식을 다시 확인
- 배운 개념 (자기 말로):
  - 같은 폴더안에 있기때문에 다른 파일의 함수를 가져올 수 있었고
  - if __name__ == "__main__": 직접 실행할때만 돌고 import할때는 돌지 않음
  - item에 사례가 들어있음
  - for 문을 통해서 페이지마다 반복해서 받게되는거고
  - w가 안적혀있으면 기본 r인거임
- 헷갈리는 것: 없음
- 복습할 것: 딕셔너리 `[키]`에는 이름표(`"totalCount"`)를 넣고 값(1463)이 나옴 · 1페이지 응답에도 전체 건수(`totalCount`)가 들어 있음 · `math.ceil` 올림(1463/100 → 15, 1400/100 → 14) · `extend`는 알맹이를 붓고 `append`는 봉지째 넣음 · `mkdir(exist_ok=True)`는 폴더가 이미 있어도 오류 없이 넘어감(파일이 아니라 폴더) · `with ... as 파일:`은 블록이 끝나면 자동으로 닫음 · 여러 줄 명령을 한꺼번에 붙여 넣으면 마지막 줄이 실행되지 않을 수 있음 → 한 줄씩 실행
- 배운 점(진행 방식): 작업을 시작하기 전에 "무엇을 위해 하는지"를 먼저 정한다
- 걸린 시간: 약 2시간
